# Final integration validation

The integration update preserves the existing native OV2640 JPEG capture/recording pipeline, SD media, motion/alarm engine, remote recipients, authentication and database ownership registry. No database migration is required for this update.

Wi-Fi attempts now finish association/DHCP before retrying, use bounded backoff, retain saved passwords only for the same SSID and commit network settings atomically. Connection success requires a real router IP. The hotspot remains a local recovery path: its “no internet” message is expected because it does not route phone internet traffic. Home-router compatibility still requires a physical test (2.4 GHz, WPA2-compatible settings, DHCP, sufficient signal/power); failure reasons appear in Wi-Fi Setup.

Cloud pairing retries transient transport failures with a persisted random operation proof. The server can return the same credential after a lost response for five minutes without weakening camera ownership, consumed-code or revocation checks. Terminal errors are actionable. Saved configuration and server-confirmed pairing are distinct statuses. A heartbeat confirms relay availability; local name changes synchronize without being overwritten by an old remote alias. Runtime endpoints follow the selected Production/Preview firmware profile.

First-use local and hosted wizards now wait for actual connection/pairing status and support naming. Local-only operation is available. Existing network/account forms are reused. The local and hosted pages share the camera-focused teal style, touch controls and English/Urdu system; technical controls remain Advanced. Browser tests cover RTL/mobile layouts and remembered sessions. Local administrator recovery requires a physical USB serial command, a one-use five-minute code, at most five attempts and a new password; remembered local sessions are invalidated while Wi-Fi, cloud binding and SD files are retained. No recovery code is exposed by HTTP. Private developer notes contain instructions only; factory setup cards are DPAPI encrypted rather than written as plaintext HTML.

Software checks: PlatformIO production-profile compile; backend authentication, authorization, recipient and pairing retry tests; network/recovery timing host tests; SQL migration repeatability/data-preservation tests; local/remote guided setup and existing browser regressions; translation coverage; relay tests. See the run report for final build sizes/deployment commit. These checks use simulated camera/provider/browser transports where described by the test output.

Physical validation remains required for router/hotspot association, reconnect after power loss, USB password recovery, OV2640/PSRAM/SD operation, recording alongside streaming, real relay FPS/memory and long-duration operation. No hardware or uninterrupted mobile-background audio claim is made. No Meta test messages are sent by these integration checks.

Normal PlatformIO builds retain the production origin. Hardware Preview builds accept only public immutable deployment metadata from ignored `.pio/preview-access.json`; they contain no Vercel bypass credential. One selected deployment exception is documented in REAL_CAMERA_PREVIEW.md. Production is not merged or overwritten.
