# Permanent Robetix Vision website

The customer address is https://vision.robetix.com. It is attached to the existing Robetix Vision Vercel project. Authoritative DNS is Vercel DNS; the existing wildcard already routes this subdomain correctly. HTTPS and the existing production dashboard were verified. No apex, portfolio, mail or unrelated subdomain record was changed.

`remote/service-origins.json` is the public source for customer and legacy addresses. The PlatformIO embed step generates `src/ServiceConfig.h`; production firmware uses the customer origin. The hosted build generates an exact-host redirect from the legacy Vercel alias. Preview API transport remains isolated through ignored `.pio/preview-access.json`. Customer pairing links display the permanent address even in a test build; installer tests must use the supplied Preview dashboard until release approval. Do not flash the production image against old service code: release the tested backend first.

Supabase Site URL is the permanent origin. Retain the exact `/auth/callback` and `/reset-password` URLs for Production and the designated Preview branch; preserve prior allowed entries and avoid broad wildcard redirects. The operator saved these settings, and real provider-generated links verified each destination without sending email. Email auth remains enabled and public signup disabled. Never rerun the base database schema or recreate owner accounts.

## Sign in and trusted devices

Email sign-in uses Supabase OTP with `create_user:false` and PKCE. The verifier and remember choice live in an encrypted, Secure, HttpOnly, SameSite cookie for ten minutes. Email opens a callback on the same browser. The app removes the code from URL history and requires Continue before exchanging it. The verifier never enters email, localStorage or JavaScript. Invalid, expired, wrong-browser and replayed callbacks fail closed. The existing password fallback and password recovery remain available; owner IDs/passwords and camera bindings are preserved.

Remembered remote sessions last up to 30 days with automatic provider-token refresh; shared-device sessions end with the browser or after 12 hours. A valid session goes directly to My Cameras. Viewing needs no extra password. Sign out clears the current cookies and provider session. Sign out on all devices records an owner revocation cutoff in the private existing `rv_rates` table and invalidates app sessions on their next API request, then requests provider global sign-out. Already issued relay tickets expire within 90 seconds. Password reset also records the cutoff. No new migration is required.

The relay checks each viewer's actual request origin against its short-lived backend-signed ticket; it has no hardcoded Vercel-origin allowlist. Consequently the permanent domain is supported without weakening viewer origin checks or changing the relay secret.

## Local camera access

A fresh camera is provisioned over its own protected hotspot using the unique private Wi-Fi credential on its setup card. It creates an internal random administrator hash and a remembered browser token; the owner need not invent another everyday password. Provisioning is closed once ownership is established and rejects requests arriving through the router interface. Existing local passwords and remembered tokens remain compatible. Local sessions are bounded to four trusted slots; another browser beyond that limit can replace an older slot. AP IP and router IP use separate browser cookies. Open camera on home Wi-Fi now issues a one-use, 60-second local handoff bound to the existing session. Its proof travels in a URL fragment, is immediately removed by the destination page, and is never sent in URL request logs. It retains the original remember preference and fails after logout, five invalid attempts, expiry or reboot. Directly typing another address/browser without the trusted link may still need physical trust once. This local HTTP handoff has the same trusted-local-network assumption as existing local login; it carries no cloud credentials. No cloud password/token is transferred over local HTTP.

Physical USB recovery can trust a browser without changing passwords or clearing settings. With the camera connected, close other monitors and run `python tools/request-local-access.py COM_PORT` using PlatformIO Python. It sets DTR/RTS inactive before opening the ESP32-CAM-MB port, requests `TRUST_DEVICE`, and displays a one-use five-minute code. Enter it under Connect this device without a password. The optional `--recover-password` path retains the earlier password-reset flow. Codes have five attempts, are held only in RAM and expire on reboot. Never put them in notes, Git or a saved terminal log. Normal CCTV needs no USB computer.

Ordinary controls reuse the existing local session. Factory Reset additionally requires the current local password or a fresh physical code, with a five-minute owner-authorization window and the existing destructive-action confirmation. Recorded media is retained by that reset. Private developer instructions remain under ignored `.private/`; real credentials belong in a password manager or encrypted provisioning card.

## Release gates and tests

The domain currently serves the previous production deployment until the owner authorizes a tested release. New code is pushed and tested on Preview first. Production environment values are prepared for the next approved build; changing them does not rebuild the current deployment. Approve a production merge/deployment only after Preview tests, then verify the permanent domain's health commit, sign-in, pairing and viewer before flashing `esp32cam` firmware. Do not promote a Preview snapshot with Preview environment variables as the production release.

Automated tests cover PKCE privacy/no-registration, remembered refresh, session revocation, real browser callback UI, local provisioning/trust UI, translations, existing CCTV controls, ownership and relay transports. Provider URL checks use an isolated temporary account and send no emails. Real email delivery/link opening, physical provisioning/trust on the upgraded device, router reconnection, real camera streaming plus recording and sustained resource use still require the corresponding hardware/browser tests. Browser simulation does not establish ESP32 throughput or mobile background audio behavior.

Passkeys are deferred: this update implements verified Supabase email-link support without adding a second identity system. Cross-origin cloud-to-local silent login is deferred because local HTTP does not provide a safe channel for cloud credentials.
